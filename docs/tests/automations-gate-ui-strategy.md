# Test strategy B5 — `automations-gate-ui`

Batch B5 of `dev-team` Lot 1, 2026-10-28. Contract: `docs/dev/kaby-proactive/specs/automations-gate-ui.md`.
Branch `feature/kaby-proactive-lot1`, worktree `kybernos-plugins-proactive`.

Six sections, each line tagged with its marker at column 0 (`e2e:`, `vision:`, `capture:`,
`maquette:`, `unit:`, `DoD:`). Every command below is meant to be pasted as is from the worktree
root; nothing here is executed at the spec stage.

Two facts this strategy is built on, both checked in the tree today:

- the live harness exists and is the only way to prove a page: `scripts/live-page.mjs`
  (`openLivePage`, signed session cookie, throw-away Chrome), `scripts/sandbox/` (`setup.sh`,
  `start.sh`, `env.sh`), `scripts/check-automations-board-live.mjs` and
  `scripts/check-suggested-live.mjs` as the patterns (seed → real clicks → `data-kb` hooks →
  `getComputedStyle` → captures → restore);
- the maquette kit of the `maquette-dsh` skill (`scripts/maquette-new.mjs`,
  `scripts/check-maquette.mjs`) is **not** in this checkout (`ls scripts | grep maquette` is empty),
  so the maquette ships its own contract script and the token extraction is done by the documented
  method (read the real GUI's computed `--dsw-alias-*` values through CDP).

## Journeys (e2e)

e2e: setup, once per machine: `bash scripts/sandbox/setup.sh` then `bash scripts/sandbox/start.sh`, then in every shell `source scripts/sandbox/env.sh` (exports `HOME`, `DSH_HOME`, `KB_HOST`; the check refuses `:3080` with exit 3).
e2e: the whole pass is one command: `source scripts/sandbox/env.sh && node scripts/check-gate-panel-live.mjs --shots /tmp/kb-gate-shots` — exit 0 = every journey green, 1 = a journey failed, 3 = no sandbox (inconclusive, never folded into a failure: `docs/dev/check-live-pitfalls.md` §6).
e2e: the check's interface, fixed by this strategy: `[--shots <dir>] [--journey j1|j2|j3|j4|j5|j6|j7|all] [--stub-model] [--before] [--no-gate] [--width <px>]`; it seeds its own automations (`id` prefix `gate-ui-`) into `$DSH_HOME/kybernos/tasks.json`, keeps a copy of the file, and puts it back in `finally`.
e2e: J1 "the gate is readable at a glance" — command: `node scripts/check-gate-panel-live.mjs --journey j1` — first proves the read path D1 ratifies: `page.eval` issues `fetch('/kybernos/tasks',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({action:'list'})})` and the check asserts the seeded `gate-ui-awaiting` object in that answer carries `gate.status === 'awaiting-approval'` with a `gate.approval` object and a `gate.staticChecks.verdict` — the payload the page already polls, no seam and no extra call; then it seeds one automation per gate status the host can produce and asserts on the list `document.querySelectorAll('[data-kb="gate-badge"]').length` equals the number of automations whose status needs a person (3: awaiting-approval, static-failed, refused), that every badge's `data-kb-i18n` is one of the three enumerated keys (`tasks.gate.badge.awaiting|failed|refused`, never a composed prefix), and that every badge's text equals `window.__KB_T__[badge.dataset.kbI18n][document.documentElement.lang === 'fr' ? 'kybernos' : 'en']`.
e2e: J1 also pins the unknown guard on a real host: `node scripts/check-gate-panel-live.mjs --journey j1 --no-gate` (see J7) renders `[data-kb="gate-panel"][data-known="false"][data-status="unknown"]`, and the check asserts no `list` response and no `tasks.json` byte ever carries the string `unknown` as a stored status (it greps the file before restoring it).
e2e: J2 "activation is refused before approval" — command: `node scripts/check-gate-panel-live.mjs --journey j2` — clicks the detail switch of an `awaiting-approval` automation, then asserts the panel opened (`[data-kb="gate-panel"][data-open="true"]`), the toast says `tasks.gate.activate.gated`, and on disk `node -e "const fs=require('fs');const t=JSON.parse(fs.readFileSync(process.env.DSH_HOME+'/kybernos/tasks.json','utf8'));process.exit(t.find(a=>a.id==='gate-ui-awaiting').active===false?0:1)"` still exits 0 (nothing flipped).
e2e: J3 "the full gesture, review → check → trial → approve → activate" — command: `node scripts/check-gate-panel-live.mjs --journey j3 --stub-model` — presses `gate-review`, `gate-check`, `gate-trial-start`, waits for `[data-kb="gate-proof"][data-state="done"]`, presses `gate-approve` (the `/kybernos/tasks` body it captured for the click must be exactly `{action:'approve', id, decision:'grant', rev}` with `rev` equal to the record's `rev` read back just before — a missing `rev` or one taken from nowhere is a FAIL), then the switch; asserts after each step the record read back by `fetch('/kybernos/tasks',{method:'POST',body:JSON.stringify({action:'list'})})` has the expected `gate.status` (`static-passed` → `trial-done`/`awaiting-approval` → `approved` → `activated`) and that `active` is `false` until the last step and `true` after it.
e2e: J3 disk half — the same journey then verifies persistence twice: `node -e "const fs=require('fs');const t=JSON.parse(fs.readFileSync(process.env.DSH_HOME+'/kybernos/tasks.json','utf8'));console.log(t.find(a=>a.id==='gate-ui-awaiting').active)"` prints `true`, and `grep -rl '"status": *"activated"' "$DSH_HOME/kybernos" --include=*.json` lists the gate store (the file name is B3's; the check discovers it instead of hardcoding it), then `page.send('Page.reload')` and a fresh `list` still return `activated` (persistence, not just optimistic state).
e2e: J4 "refusal" — command: `node scripts/check-gate-panel-live.mjs --journey j4` — presses `gate-refuse`, confirms in `KbConfirm`, asserts the captured body is `{action:'approve', id, decision:'refuse', rev}` (B3's vocabulary, the record's `rev`) **and** `gate.approval.state === 'refused'`, `active === false`, the switch still routes to the review (a click opens the panel and sends nothing), and the panel offers `gate-check` again.
e2e: J5 "a trial that touched the outside cannot be approved" — command: `node scripts/check-gate-panel-live.mjs --journey j5 --stub-model` — the stub endpoint answers with a write tool call; asserts `[data-kb="gate-proof"]` shows `sideEffectFree === false` (`data-sideeffect="false"`), `gate-approve` is `disabled`, `gate-refuse` is enabled, and the proof lists the call as `refused-as-write`.
e2e: J6 "two tabs" — command: `node scripts/check-gate-panel-live.mjs --journey j6` — opens a second page on the same sandbox, approves in page B, asserts page A shows `approved` after its own 15 s poll and that no state was written by page A (`localStorage` untouched: `Object.keys(localStorage).filter(k=>/gate/i.test(k)).length === 0`).
e2e: J7 "degradation" — command: `node scripts/check-gate-panel-live.mjs --journey j7 --no-gate` — the check strips `task.gate` from the seed and answers `{ ok: false, error: 'unknown action: gate-check' }` to the gate actions through a page-level `fetch` wrapper; asserts the panel renders `unknown` with `tasks.gate.unavailable`, no red banner (`.kba-banner` absent), the initiative block absent, and the switch behaves as before the batch (calls `toggle`).
e2e: the trial poll is bounded, and J3 asserts it: the check counts the `/kybernos/tasks` POSTs whose body is `{action:'trial-report', id}` (B3's only body for that action, § 3.2) and requires ≤ 30 for one trial and 0 once the answer carries a `report` whose `outcome.state !== 'open'` (a poll that never stops is a failure, not a detail).
e2e: J2/J3/J4 are replayed **after** J7 on the same run (`--journey all`) so a permissive fallback cannot hide behind a clean first pass.
e2e: cleanup is part of the journey, not a courtesy: the check deletes its `gate-ui-*` automations, restores `tasks.json` byte for byte (`copyFileSync` backup + `renameSync`), removes the stub endpoint, and fails if `$DSH_HOME/kybernos/tasks.json` differs from the backup at exit.

## Vision (before/after, read with the session model)

vision: the "before" state is produced by the same check, on the client without this batch: `git stash push -- packages/kybernos-plugin/client.js && node scripts/check-gate-panel-live.mjs --journey j1 --before --shots /tmp/kb-gate-shots/before; git stash pop` — `--before` asserts the **absence** of `[data-kb="gate-panel"]`, `[data-kb="gate-badge"]` and `[data-kb="initiative-block"]`, so this run is red on the batched client and green on the stashed one.
vision: the "after" state is the same command without `--before` and with `--shots /tmp/kb-gate-shots/after`; both runs use the same seed (same automation names, same statuses), the same window (1400×900), the same theme and the same zoom, so a pair is comparable.
vision: every PNG of the after run is opened with `read_image`, one by one, before any verdict — a capture nobody opened is not evidence; the one-line observation of each goes into the header comment of `scripts/check-gate-panel-live.mjs` under "What was seen".
vision: the before/after pair is compared on three things, in this order: (a) the new block is present and the rest of the page is unchanged (`[data-kb="page-automations"]` height delta ≤ 60 px, `#` of list rows equal, the toolbar's box identical), (b) the new block's geometry matches the host panel template `[data-kb="suggested-block"]` within 1 px on `border-radius` (16 px) and `padding` (`12px 16px` on rows), (c) the labels are the French twins in the French GUI and the English ones in the English GUI, read off `data-kb-i18n` (never judged by eye).
vision: the reference for homogeneity is **measured, not felt**: the check records `getComputedStyle` of `[data-kb="suggested-block"]` and of `[data-kb="gate-panel"]` (`borderTopLeftRadius`, `borderTopWidth`, `borderTopColor`, `backgroundColor`, `fontSize` of the title and of a row, `height` of a row) and prints both objects in the log; a difference on radius, border colour family or font-size ladder is a FAIL, a difference in height is printed and judged.
vision: accent and truncation are checked on the captures too, because the panel is text-heavy: each findings row's `scrollWidth <= clientWidth + 1` (no clipped message), every `title` attribute present on a truncated label, and one capture taken with a 160-character finding (the longest the cap allows) to see how the row folds.
vision: the dark state is the app's own dark theme, driven the way `check-flow-dark-live.mjs` does it (`title === 'Dark theme'` button, then `'Light theme'` back), and the check asserts the switch really darkened the page before capturing (luminance of the centre pixels of `[data-kb="gate-panel"]` < 0.2 in dark, > 0.6 in light) — a "dark" capture of a white panel is a false proof.
vision: the narrow state is measured at 480 px (`Emulation.setDeviceMetricsOverride`, or the check's `--width 480`) and judged on the capture: the status line and the next step share one line, the findings wrap, the buttons go full width, and `document.documentElement.scrollWidth <= innerWidth + 1`.

## Unit (pure logic, the harness it joins)

unit: the file is `packages/kybernos-plugin/test-automation-gate-client.mjs`, run alone by `node packages/kybernos-plugin/test-automation-gate-client.mjs` from any directory (it resolves `client.js` through `import.meta.url`, as `test-automation-runs-client.mjs:11` does) and discovered with no registration by `node scripts/run-all-tests.mjs` (`packages/*/test*.mjs`, cwd = the bundle) and by CI's same loop.
unit: extraction follows the house pattern of `test-automation-runs-client.mjs:11-21`: `src.split('// KB-AUTOBOARD-BEGIN')` and `src.split('// KB-AUTORUNS-BEGIN')`, exactly one block each, then `await import('data:text/javascript,' + encodeURIComponent(block + '\nexport { … }'))` with the explicit name list.
unit: the third extraction is the new UI region: `src.slice(src.indexOf('// <kbgate-ui>'), src.indexOf('// </kbgate-ui>'))`, once, non-empty; its source assertions (§9 of the spec) run on that slice.
unit: the `KB_T` table is parsed line by line (`/^\s*'([A-Za-z0-9_.]+)':\s*(\{.*\}),?\s*$/`, `eval` of the literal) as `test-tasks-client.mjs:17-22` does, and a `kbt` twin with a settable language drives the expected texts.
unit: invariant #1, the core case: for the 9 statuses × 4 approval states × `active` true/false, `kbGateToggleIntent` returns `'activate'` **only** when `approval.state === 'granted' && (status === 'approved' || status === 'activated')`, and `'deactivate'` whenever `task.active !== false`; the test prints the count of the 72 combinations and fails on the first mismatch with the combination in the message.
unit: refusal guard: `kbGateCanRefuse` is `true` for the 6 frozen statuses other than `activated` and `refused` (draft, static-failed, static-passed, trial-done, awaiting-approval, approved), `false` for `activated`, `refused` and `unknown` (a host that checks nothing cannot be refused on your behalf).
unit: ladder: `kbGateSteps` gives `next === 'approve'` for `awaiting-approval`; `'review'` for
`draft`/`static-failed`/`static-passed`/`trial-done` **and for `refused`** (a refused record is not a
dead end: it goes back through the checks, and `kbGateCanRefuse` is `false` on it, so the ladder never
offers a second refusal); `'activate'` for `approved` with a granted approval; `null` for `activated`
and for `unknown`; `steps[1].blocked === true` whenever `approval.state !== 'granted'`. The case
enumerates all nine statuses, so a status that no branch matches fails instead of falling through
(the refused-unpinned finding).
unit: approval guard: `kbGateCanApprove` is `false` on `awaiting-approval` with no trial, `false` when `trial.sideEffectFree === false`, `false` when already granted, `false` for every other status, `false` when `rev` is `null`, `true` only for the one good combination; and the body the view produces is asserted to be exactly `{ action: 'approve', id, decision, rev }`, with `rev` copied from `kbGateOf`'s record (B3 answers `rev required` otherwise and `stale` when it moved).
unit: bounds and honesty of `kbGateFindings`: 30 findings (12 blockers, 10 warns, 8 infos) → `rows.length === 20`, `hidden === 10`, `blockers === 12` (over all of them, not the drawn ones), order blocker → warn → info, a 400-character message cut to 160 with `…`, control characters replaced by spaces, `field` kept verbatim up to 60 characters, non-object entries skipped without throwing.
unit: proof: `kbProofOf({trial:null})` → `present:false`, `sideEffectFree:null` (never `true`); a `ProofReport` with `sideEffectFree:false` and one `refused-as-write` call → `refused === 1`, and `refused` still counts a call that the 8-row cap clipped; `durationMs` from `startedAt`/`endedAt`, `null` when `endedAt` is null or unparsable; 9 effects → 5 drawn + `effectsHidden === 4`; strings trimmed to 120 characters.
unit: tolerance to a hostile host: `kbGateOf(null)`, `kbGateOf([])`, `kbGateOf({gate:{status:'pizza', approval:'x', staticChecks:7, trial:'no'}})` all return `{ known: false, status: 'unknown' }` without throwing; `kbGateError('unknown action: gate-check') === 'unknown-action'`, `'refused_on_phone' → 'phone'`, `'sign-in required' → 'signin'`, `'approval required' → 'approval'`, `'task not found' → 'not-found'`, anything else `'other'`.
unit: initiatives through `kbInitView`: 10 items with `cap 8` → `items.length === 8`, `hidden === 2`; an entry with `nextAction:{kind:'send'}` → `usable:false`, counted in `skipped`, still drawn; items that are not objects, have no `id`, or repeat an `id` are dropped; `evidence` of a non-object becomes `{n:0,span:'',where:''}` (the card shows the absence, it does not crash).
unit: i18n completeness, the discriminating half: every one of the 94 keys of §7 of the spec exists in `KB_T` with **both** a `kybernos` and an `en` value, non-empty, and no key is defined twice (a duplicate row silently wins in the object literal — the parser counts occurrences before collapsing). unit: i18n usage: every `kbt('…')` literal inside the `<kbgate-ui>` region and inside the two appended pure blocks belongs to that declared list (a typo'd key fails here instead of showing a raw key in the UI), and the region contains no French prose outside `kbt(` (the gate region is new code: English only, and accents are the tell on this unaccented bundle).
unit: the badge rules: `kbGateBadge` returns the **full** key `tasks.gate.badge.awaiting` for
`awaiting-approval`, `tasks.gate.badge.failed` for `static-failed`, `tasks.gate.badge.refused` for
`refused`, and `''` for the other six statuses — each returned value is asserted to be present in the
parsed `KB_T` table, and the `<kbgate-ui>` slice is asserted to compose no key at all (no
`'tasks.gate.badge.' +` and no template literal whose head is that prefix), per § 7 of the spec;
`kbGateTone` maps
activated/approved to `'ok'`, **`awaiting-approval` and `trial-done` to `'warn'`**, static-failed and
refused to `'bad'`, draft/static-passed/unknown to `'idle'` — the exact table of the spec, so
`trial-done` reads `'warn'` on both sides (the tone-drift finding;
the frozen value is `'warn'`).
unit: the read path is the list, and only the list (D1): every fixture is a raw task object of B3's `{action:'list'}` answer (`{ id, …, gate }`), never a gate minted on the side; one case feeds a two-task list (one carrying `gate`, one without) through `kbGateOf` and asserts the first is known with its own status while the second is `unknown` — a defaulted or shared gate is exactly what D1 rules out, and no seam stub or file fixture is allowed to inject one.

unit: source contract of the panel (§9 of the spec, all asserted on the `<kbgate-ui>` slice): no `fetch(`, no `window.open`, no `localStorage`, no `setInterval` other than the single bounded trial poll, no `dangerouslySetInnerHTML`, no `'approve'`/`'trial-start'`/`'gate-check'`/`'toggle'` inside a `useEffect`, no `autoFocus`, no `host.call` (I/O comes from props), and the four cap constants are the ones used by the `slice(` calls.
unit: source contract of the page wiring: the three switches (detail `23111`, list `23239`, card `21166`) all go through `kbGateToggleIntent`, asserted on the source by `kbGateToggleIntent(` occurring at least three times and `act('toggle'` never occurring without a preceding intent check in the same row block.
unit: "the client never decides the gate": the two appended pure blocks contain no cron regex, no timezone check, no prompt scan (`/\bcron\b/` only inside comments, `/toLowerCase\(\)\.includes\(/` absent), and `verdict` is only ever read from the record, never computed.
unit: CSS of the new surface, asserted on the source: the `kbgate-*` block appended after the suggested-automations rules (`client.js:31360`) carries no `#` hex and no `rgb(`/`hsl(` (only `var(--dsw-…)` and `color-mix` over tokens), every `font-size` in it is one of 11.5 / 12.5 / 13 / 14, every `border-radius` is 12, 16 or 999, and it holds `@media (max-width:640px)` — the same breakpoint as the sibling block it sits next to, so the two surfaces fold together (the homogeneity criterion, measured instead of asserted by eye).
