## Process findings

1. **A script case does not need a model.** A Haiku tester cost 71k to 99k tokens on a trivial case. The runner decides script cases; Haiku is kept for agent cases and a one-in-five cross-check.
2. **The named agent is not available in the session that creates it.** `takeoff-tester` loads at session start.
3. **A failing check is not a failing product.** W1-02 was red for stale assertions and a missing media folder. Triage has to separate test, environment and product before a ticket counts against the product.
4. **Green is not covered.** The suite is green with 27 kinds of skip, among them the rendered cloud client that the Cloud budget work will change. A skip is listed in every run summary and never counts as a pass.
5. **Media are not in git** (`AGENTS.md` rule 4), so every check that plays a clip or a picture needs its folder given explicitly, or it must skip.
6. **A tester tool is a part of the test.** The first « fail » of W1-20 was the shared click helper (a hidden duplicate button, a click before the page was ready). The walk driver now clicks the visible element on top; a case that fails for a tool reason is closed as `tool`, not counted against the product.
7. **The leftovers sweeper stops sandboxes in the middle of a run** (no client for ten minutes, or older than three hours; a headless viewer does not always count as a client). The runner has `--before`, and a watcher loop restarts a stopped sandbox. The lasting fix is a `sandbox.keep` marker in the sweeper, which is the owner's tool.
8. **`source scripts/sandbox/env.sh` changes `HOME`.** A recipe with `~` after it points into the sandbox. Absolute paths only.
9. **The replica session of an account lasts about two hours, and « connected » stays true after it.** `e2e-connect.mjs --force` (disconnect, pair again) fixes it; the sandbox is restarted afterwards.
10. **A killed live check can leave the sandbox changed.** W1-14 left a stand-in server registry with the model service switched off: every chat then failed with « not signed in » and four creation walkthroughs came back blocked. The cause was found by reading the server profile the plugin uses, not by the symptom. Look at `kybernos/servers.json` and the live-gate files after any timeout.
11. **The stand-in model of the replica answers one fixed sentence.** It proves the model path works, not that anything can be created with it: the creation cases need another model.
12. **Do not edit the repository while a tester runs.** It voids `repo_clean`: two Haiku verdicts were lost to it.
13. **W1-01 and W1-24 need an unpaired sandbox** with `onboarding.json` set to `completed:false`; and the sandbox is a clone of the owner's profile, not a fresh install.
14. **Haiku is good at measuring and at walking, weak at reading what a screen means.** Its « fail » verdicts were findings, not defects: each needs a script or a second look before it counts (T-011, T-012).
15. **A plan that says « on » must be checked as « on ».** The first freeze only removed what the plan marked off; five bundles marked on stayed disabled by the owner's own patch, and nothing noticed for a whole wave (T-014). The freeze now enables them.
16. **« Did not open » and « not run » are not a pass.** The phone-width check printed 2 ✓ and 16 ○ and exited 0 (T-015). A run summary has to show the skips next to the passes, and a case with more skips than checks is read as blocked.
17. **A case that needs two opposite sandboxes is two cases** (T-017): a connected account (A) and a never-paired one (C) cannot share one command.
18. **A chained command hides what comes after its first failure.** W1-05 and W1-08 chain several scripts with `&&`: the later ones had never run before the earlier ones went green (the help check and the i18n audit).
19. **The stand-in model is a control port, not a fixed sentence.** `POST :8822/__/engine/reply` and `/__/engine/fail` on the replica set what it answers, how many tokens it bills and which provider calls fail; that is what makes the failure and credit cases (W2-08, W2-09) playable without a real model or a real key. Finding 11 is true of the default only.
20. **A case title must say what its script proves.** W2-05 and W2-06 promised a real local turn and working free models; their scripts check a search and a locked state. The titles were corrected and the missing half became W2-12 and question 14.
21. **A harness command that is not idempotent is a trap.** `e2e-teams-run.sh up` re-clones both sandboxes and recreates the accounts; `down` deletes the sandbox homes. The README says to use `preflight` and `run` only, and the keeper script is the only thing that restarts a sandbox.
22. **A journey may depend on another one.** J5 crashed because account B was not yet in T1; only J4 (W4-09) makes it so. Dependencies between journeys are now in the W2 runbook and in the case note; the harness's `run` with no argument runs them in the right order.
23. **A check can leave the sandbox in a state that breaks the next one.** Account A came back on the first-run wizard (`onboarding.json` `completed:false`), which blocked every chat and made the harness preflight fail with « no request reached the replica ». Whoever left it (a W1 onboarding case run on A is the suspect) is not known; the preflight caught it, and a diff of `onboarding.json` of A, B and C is now the first thing to look at.
24. **Turn a walkthrough into a script when the screen text is mechanical.** W2-08 was an agent case; as a script (`check-model-failures-live.mjs`) it costs no model token, runs in two minutes, prints the sentences for a human to read and found a real defect (T-021) that a Haiku walk would only have described.

State: `open` | `fixed` (case and ring green) | `closed` (not a product defect, or not seen again) | `to triage` | `to confirm` | `flaky` | `wontfix` (owner decision, with the workaround) | `escalated` (3 attempts).
25. **A full pass of the journeys spends the replica.** J5 uses the 5-hour allowance of a member for good, J6's pool fill uses T3's pool and A's 7-day allowance, and the sessions of both accounts last two hours: a second pass finds every chat refused. `bash scripts/e2e-teams-run.sh replica-reset` and `scripts/soft-takeoff-repair.sh` give a clean replica in a few minutes (README § 7c); copy the proxy log and the `result-J*.json` first.
26. **Size a test turn on what it cost, not on how many calls it made.** J5 guessed the cost from a request count that changes from turn to turn (title, classification, a retry after a 429); it overshot three times (T-020). The server's own spend after a calibration turn is the truth.
27. **After a removal the DSH may be unusable until it is paired again.** J7's removal step cannot be replayed on the same pairing (the card cannot go back to the team: `goTo` failed); replay it after `replica-reset` and a re-pair.
28. **A server plan needs its own replica.** The harness replica is configured for the journeys (accounts spent, features off, a recording proxy): the server's acceptance plan run on it reports the environment as defects. A dedicated replica on other ports with the plan's switches cut the reds from 41 to 30 and showed which are about the plan against the catalogue (T-027).
29. **A rename is a test change too.** « Add credits » became « Add budget » and a role refresh moved to the team's own DSH: two of the four W4 journey reds were stale checks (T-024, T-030), which is why a journey red is read as test, environment or product before it is a ticket (finding 3).
30. **Read the whole repair output before a replay.** The first replay of J7 on the fixed client ran on a stopped sandbox A and an unpaired B (16 reds, « Sign in again » on every screen); the preflight had said `PREFLIGHT FAILED` and the command cut the output with `tail`. A journey run is only valid after a line `preflight ok` for both accounts.
31. **A sandbox cloned from the owner's profile inherits his default agent preset.** His is `minimal`, whose system prompt is one line and has no plugin sections: every check that looks for what a plugin puts in the prompt (memory, team lessons, the memory-off marker) reads « absent » and looks like a product defect (J2, 13/16 ticketed for a day). The harness now pins `standard` next to the model (`pin-model.mjs --preset`). Before ticketing a missing prompt block, read the system prompt of the request: a one-line prompt is the preset, not the plugin.
32. **A test that sends right after another member's change must wait for the other side's cache, or restart it.** A team DSH re-reads the approved lessons every 5 minutes at most; a check of « the member sees what the owner approved » is either a 5-minute wait or a start of the member's DSH after the approval (J2 does the second).
33. **A check that points a sandbox at its own stand-in server needs a sandbox the recette has not pointed at the replica.** The recette keeps A, B and C on the replica's address (`KYBERNOS_CLOUD_API`, the default of `soft-takeoff-sandbox-up.sh`): the phone check wrote its stand-in into `servers.json`, the plugin kept talking to the replica, the replica refused the stand-in's token and the DSH ended the session (« Sign in again », a `.ended` file). 14 reds that looked like a broken phone page.
