# Sharing a dashboard: snapshots (static level)

Decided with the owner on 2026-11-02. A dashboard over a Tables object can be shared in two ways. This page is the **static** level, built in `packages/kybernos-db/share/`;
the **dynamic** level (a live web app on the person's own cloud computer, with a shared-password mode) comes later and reuses the same page with a live data source.

## What is shared

A **snapshot**: what the widgets of the dashboard showed on the day it was made. Never the table, never a row beyond the few a `table`/`list` widget prints, never a field the
Dashboards plugin keeps back (`sensitive`, `secret`). It is a photograph: it does not follow the table. Refreshing it = publishing again to the same link (an Automation can do it).

Left out, and said in the answer of `dashboard_share check` with the reason: widgets about this computer rather than a table (usage, sessions, automations), widgets the page
does not draw yet (kanban, carousel, calendar, flow, sankey), and widgets that would print a `personal` field as text (a chart "by customer" is a list of names) unless the person
agreed (`includePersonal`, a card repeats it).

## Pieces (all in `packages/kybernos-db/share/`)

| file | what |
|---|---|
| `snapshot.mjs` | builds the snapshot from a dashboard through the Tables door, with the Dashboards plugin's own model (a vendored copy, `vendor/`, kept equal by `scripts/vendor-share.mjs` and a test) |
| `seal.mjs` | optional password: PBKDF2-SHA256 (600 000 rounds) → AES-256-GCM in the browser; the server only ever holds ciphertext |
| `render.mjs`, `boot.mjs`, `viewer.css`, `viewer.mjs` | THE page: one script, one style sheet, an empty root. A snapshot is drawn as text nodes and SVG shapes, never as HTML |
| `service.mjs` | the verbs `check`, `file`, `publish`, `list`, `revoke` and the local record of links; the tool `dashboard_share` (agent/tools.mjs) is a door onto it |

No new interface: the agent does it in the chat (`dashboard_share`, a card before anything leaves the computer). Without a `snapshots` port there is no link; `file` writes one page
the person keeps or sends by hand (`<DSH home>/kybernos/shares/<dashboard>-<day>.html`, opens offline in any browser).

## The snapshot document

```json
{ "kind": "kybernos-snapshot", "version": 1, "title": "Sales", "desc": "…", "made": "2026-11-02",
  "widgets": [ { "id": "revenue", "type": "card|chart|table|list|note", "title": "…", "w": 3, "h": 2, "data": { … } } ] }
```
`data` is the result of the widget, already formatted (a number, the points of a chart, the cells a table prints): the page has no model and no formula. At most 24 widgets;
a snapshot is at most 1 000 000 bytes as text. The page ignores any `kind`/`version` it does not know.

## The sealed envelope (protected link)

```json
{ "kind": "kybernos-snapshot", "version": 1, "sealed": true,
  "kdf": { "name": "PBKDF2", "hash": "SHA-256", "iterations": 600000, "salt": "<b64url 16 bytes>" },
  "cipher": { "name": "AES-GCM", "iv": "<b64url 12 bytes>" }, "data": "<b64url ciphertext of the snapshot JSON>" }
```
Additional authenticated data: `kybernos-snapshot/1`. The page accepts 100 000 to 2 000 000 iterations. The password is generated by the plugin (100 bits, shown once) and kept
only in `<DSH home>/kybernos/shares/index.json` (mode 600) so that an update keeps the password the readers were given. The envelope carries no title: the server learns nothing.

## The `snapshots` port (what the Kybernos account gives the plugin: `options.snapshots`)

```js
{ limits?: () => { maxBytes, maxCount, ttlDays },
  put:    async ({ id?, sealed, text }) => ({ ok: true, id, url, expires, bytes }) | { ok: false, error, message },
  remove: async (id) => { ok: true } | { ok: false, error, message } }      // error 'not_found' is fine: the link is gone either way
```
`text` is the JSON of the snapshot or of the envelope. `put` without `id` makes a link; with `id` it replaces the content of that link (error `not_found` when it expired or was
taken down). The port is absent by default and nothing breaks: the tool answers `unavailable` and points at `file`.

## What the server (kybernos-server, its own session) has to do

- Store `text` per link: validate it (JSON, ≤ limit, a snapshot of the shape above or a sealed envelope; **never store or serve anything else, no HTML**); id = 16 random base32 characters (80 bits), unlisted, no index.
- `GET /s/<id>` → the page (`node scripts/share-viewer-build.mjs --out <folder>` writes `viewer.html` and `policy.txt`; the same bytes for every link) with `Content-Security-Policy: <policy.txt>`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`. A link that does not exist or expired still gets the page (it says "could not be loaded") or a 404 page: either is fine.
- `GET /s/<id>.json` → the stored text, `application/json`, no CORS headers, `Cache-Control: public, max-age=60` (a revoked link disappears within a minute), 404 `{}` when gone.
- `PUT/DELETE` with the account's session: the account owns its links; quotas (`maxCount`, `maxBytes`, `ttlDays` since the last update); a deleted account takes its links down.
- Domain: `kaby.app/s/<id>` needs no wildcard certificate. Abuse: a link can be taken down by the owner of the platform; since a snapshot is data drawn by our own page, it cannot host a phishing form or a script.
- Rebuild the page files (and take the new policy) whenever `packages/kybernos-db/share/` changes.

## Open decisions (the owner's)

Who may publish (free accounts?), the numbers (my default: 1 MB per snapshot, 20 links per account, 90 days since the last update), the link domain, who answers an abuse report.
